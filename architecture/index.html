Agents vs Wall Street · 16 August 2026

Aquara

An analyst agent that reads the filings itself, is not allowed to state a number it cannot quote, and hands every figure to a causal backtest that decides — from unseen evidence alone — whether the model is trusted over the filing.

How it works

One command turns a manifest of four companies into four completed OpenStocks workbooks. The path from a ticker to a number has five stages, and each one is allowed to refuse.

The final command

uv run --with-requirements agent/requirements.txt python -m agent.run
npm run check:forecasts

It processes all four companies in one process, writes the four workbooks by filling only the forecast cells of the supplied templates, and emits a nested-evaluation report. Nothing is uploaded programmatically — a person checks the files and uploads them to OpenStocks by hand.

Research and financial reasoning

The agent reads; it does not guess

Each of the twelve targets has an analyst brief written the way you would brief a junior analyst: the exact basis wanted, and the traps to avoid. Home Depot's brief says total-company comparable sales in percentage points and explicitly rules out the U.S. figure. Analog Devices' EPS brief says adjusted, not GAAP, and to return null rather than substitute. Deere's segment brief says the operating profit of Production & Precision Agriculture, not its net sales.

The agent then reads the candidate filings and returns the figure that document reports for its own period, plus the sentence it took it from. Reporting the current period only is the whole discipline: filings restate prior-year comparatives and year-to-date totals right next to the current number, and those are the traps that quietly corrupt a backtest.

Why the numbers stay auditable

The agent extracts reported historical facts, never a forecast. That boundary is what makes the output checkable: a claimed fact has a source sentence, and the sentence either is in the document or it is not. Forecasting is left to the deterministic statistical layer, where the choice of model is decided by measured performance on unseen data rather than by anyone's opinion.

The one check that does the most work: an extraction is discarded unless its supporting quote appears verbatim in the source document. A model that invents a plausible sentence fails this immediately, and a model that paraphrases a real one fails it too. This is cheap, and it is the difference between a citation and a decoration.

Conflicting evidence

Hays publishes a short canonical release and a very long duplicate on the same day, and the long one repeats its financial statements thousands of lines later. Ranking by filename or taking the largest matching number selected weighted-share counts as earnings per share. Same-period candidates are now ranked by exact label match, position in the document, plausibility and first-report timestamp.

Where a metric has both an agent reading and a deterministic parser reading, the two are compared and every disagreement beyond 2% is recorded. The agent's reading wins, because it is the only one that can show its evidence: a sentence checked to exist in the document and to contain the number being claimed.

The disagreement that settled this design. For Analog Devices' Q3 2020 revenue the parser returned 8,200 and the agent returned 1,456. The quarter's 10-Q states Revenue $ 1,456,136 in a thousands table. The parser had matched “expected revenue of $8.2 billion on a pro forma basis” — a combined-company figure from the Maxim merger announcement, in a different document, about a different entity, for a different period. Our first policy was to drop any period where the two disagreed; that policy would have discarded the correct reading and then fallen back to the series containing the wrong one. Deferring to whichever reading is corroborated by its own quote is what fixed it, and ADI revenue's measured skill went from 49.8% to 62.1% as a result.

Important design choices

The model never picks the number

The obvious build is to show an LLM the filings and ask for a forecast. We rejected it because it cannot be audited: when the answer is wrong there is nothing to inspect. So the LLM was given the job it is genuinely better at than a regular expression — reading prose and tables written by humans — and the forecast itself is produced by models whose historical error is measured.

Selection is nested and causal, not chosen in hindsight

Picking the configuration that performed best over the whole history and then quoting that history as evidence is the standard way to fool yourself. Instead the configuration for each target is selected using only origins strictly before it, and performance is reported only on targets the selection never saw. The deployment recommendation is computed separately and excluded from the reported skill.

A gate that is allowed to reject our own work

A nested forecast replaces the filing-based one only with at least three unseen outer origins, positive outer skill against a paired seasonal-naive baseline, no fallback to that baseline, and positive deployment-ensemble skill. It currently rejects five of twelve metrics — including all three Hays metrics, where the machinery works but has no measured edge.

Reproducibility over cleverness

Completions are temperature 0 and cached to disk by request. Once the cache is warm the final run makes no network calls at all, so it reproduces offline and byte-for-byte. The workbook writer starts from the supplied template and locates the header row using the same rule as the organisers' checker, so the sheet the checker validates is left structurally untouched.

What we tried and abandoned

  • Hand-written regular expressions for reading. They worked until they did not, and their failures were silent — a pattern would match a nearby number in a different row. Replaced by the research agent with a quote requirement.
  • Substituting GAAP EPS where adjusted EPS was missing. It would have removed a skip and made coverage look better. It is a different metric, so the skip stays.
  • Treating Hays fiscal years as a quarterly axis. Its H1/FY reporting is semiannual; forcing season 4 onto it produced meaningless seasonal comparisons. It now runs on season 2 with its own pre-registered protocol.
  • A second methodology (historical-analogue matching with weighted scenarios) and an LLM orchestrator choosing between the two per metric. Built and explored on a branch. It is not in the submission path: it bypasses the causal evidence gate, and we were not willing to swap a measured selector for an unmeasured one on the day.

The gate was proven to reject before any pass was believed

A validation gate that has only ever seen good input is not evidence of anything. tests/test_research.py drives every rejection path with a stubbed driver: a fabricated quote, an implausible value, a missing quote, self-declared low confidence, a non-numeric value, and an honest refusal. Writing those tests caught two real defects — a shared cache was serving the first case's answer to all later cases, so all six gates falsely appeared to pass, and the excerpt builder overran its character budget by the length of its own separators.

Measured outer performance

All twelve metrics now have enough first-report history to score honestly. Across 28 company-local outer rounds the nested policy produced 83 unseen predictions at an aggregate relative MAE of 0.783 — a 21.7% improvement on the paired seasonal-naive baseline.

Before the research agent read the corpus, only ten of the twelve metrics could be scored at all, on 66 predictions, for 21.9% skill. Reading the filings properly did not inflate that headline — it is the same number measured over a fifth more evidence, with the two previously unscoreable metrics brought in and judged on their merits. One of them, Home Depot's comparable sales, earned its way past the gate at 37.9%; the other did not.

Adding a candidate model without touching the code

The graph page carries a hot-swap form. Paste a JSON node — id, label, which metric kinds it applies to, and a spec such as {"type": "ewma", "alpha": 0.4} — and Validate runs the same pre-live check the agent runs. Validate + Save writes it to agent/nodes/models/, where it competes against the existing candidates on the next run. It still has to beat seasonal naive through the same nested selection to reach a workbook: the door is open, the gate is not.

The graph is generated, not drawn. Both SVGs are built from the live manifest and forecast objects at request time, so the picture cannot drift away from the code the way a hand-maintained diagram does. This app is a development and inspection surface, not part of the submission path — the submitted workbooks come from the single command above it.

The clear-run evidence log

Every run writes a timestamped record to logs/clear-run.md: the final command and commit, the series source, and — per metric — whether the guarded gate promoted the nested ensemble or fell back to the sourced direct forecast, with the reason. Those fallbacks are the retries the challenge asks us to disclose; nothing is hidden, and API keys are stripped from the text. The graph run and /output offer a one-click ⬇ download that bundles the four workbooks with this log — the four number files and one timestamped record, which is exactly what a reviewer needs to check a run.

Two layers we built for comparison, not for the number

Before selection the pipeline runs an autonomous provisioning step: for each metric an agent reads a catalogue of what features actually exist and each methodology's input requirements, and decides how to provision them — bounded by a deterministic feature-control (enough history, non-degenerate variance, coverage) that it is not allowed to override. We also built a second, independent Methodology 2 — historical-analogue matching with evidence-weighted Bear/Base/Bull scenarios — and compare it against Methodology 1 in /report. Both are inspection and comparison surfaces: the submitted twelve numbers come from the guarded-nested Methodology 1 path described above, and neither layer can move a figure past the evidence gate.

Known weaknesses and what comes next

The four direct forecasts are the weakest numbers we are submitting — they are the ones the evidence gate declined to promote, so they rest on stated assumptions rather than measured skill. We would rather name them precisely than average them into a headline.

  • The direct bridges carry approximations we can point at. Deere fixes diluted shares at 271m and the Q3 share of second-half net income at 0.57, and estimates segment profit at roughly 55% of net sales on an 18% margin — the nested forecast overrides that last one, and the two differ by about a factor of two. The Hays EPS bridge applies an after-tax-per-share ratio instead of the full accounting identity. Reading each constant from the filing is the next change, in that order.
  • Coverage limits we declined to paper over. Home Depot's adjusted EPS is a recent non-GAAP disclosure; the agent found nine observations where the parser found seven, and refused on the other forty filings because they state GAAP EPS only. That is now enough to score, and it scores 0.0% — so it stays direct on measured merit rather than for want of data. All three Hays metrics backtest cleanly and show zero to slightly negative outer skill: a working pipeline, reported as working rather than as useful.
  • Retrieval is keyword-based and each document is read once. Wording we did not anticipate never reaches the agent, and the agent cannot ask for a document it was not given. A second independent read with disagreement arbitration is the clearest next gain and is already scoped.
  • The plausibility bounds are hand-set. They catch unit and order-of-magnitude errors, not a wrong-but-reasonable number — which is exactly why the verbatim-quote requirement, not the bounds, is the load-bearing check.

Three decisions stay with a human: the analyst briefs, the plausibility bounds, and whether to trust the gate when it overrides a filing-based number by a wide margin. Submission is also deliberately manual — a person checks the four workbooks and uploads them.

How to reproduce the final run

Final commit: HASH

Final command: uv run --with-requirements agent/requirements.txt python -m agent.run

Expected output: four completed workbooks in submission/.

Requirements: Python with uv, Node for the organisers' checker, and the repository's frozen corpus. An OPENAI_API_KEY in .env enables the research agent; the cached completions are committed, so a reviewer reproduces the submitted numbers without a key and without network access. Running with no key and a cold cache falls back to the deterministic parsers, which is a different and clearly labelled configuration.

The company and metric specification is not hard-coded into the run: it is read from challenge/companies.json, and the metric labels, units and fiscal-period header in each workbook are matched against it. 

cp .env.example .env          # set OPENAI_API_KEY
uv run --with-requirements agent/requirements.txt --with pytest python -m pytest -q
uv run --with-requirements agent/requirements.txt python -m agent.run
npm run check:submission
